# v2 설계: 마이페이지 + 다중 여행계획

작성일: 2026-09-06
대상: `travel-template-v2` (단일 파일 `index.html`)
전제: v1 데이터는 옮기지 않고, v2는 Firestore를 새로 사용한다. v1은 코드(HTML) 백업일 뿐이다.

---

## 1. 목표

로그인한 사용자가 여행계획을 **여러 개(최대 5개)** 저장·관리할 수 있게 한다. 로그인을 앱 사용의 전제로 만들고, 로그인 후 첫 화면을 "마이페이지"로 둔다. 여행 편집기 자체의 기능(일정·메모·링크·지출·PDF·공유·수정/보기 모드)은 **바꾸지 않는다** — 저장 위치와 진입 경로만 바꾼다.

---

## 2. 화면 구조

4개 화면을 `index.html` 한 파일 안에서 show/hide로 전환한다. 화면 상태는 JS 변수 하나(`screen`: `'landing' | 'mypage' | 'settings' | 'editor'`)로 관리한다. 실제 URL 라우팅은 하지 않는다(뒤로가기 등은 이후 과제).

```
[비로그인]
  ① 표지(landing)  ── 구글 로그인 성공 ──▶  ② 마이페이지(mypage)

[로그인]
  ② 마이페이지  ──여행 카드 탭 / 새 여행──▶  ④ 편집기(editor)
  ② 마이페이지  ──⚙ 내 정보 및 옵션──▶       ③ 설정(settings)
  ④ 편집기      ──← 마이페이지──▶            ② 마이페이지
  ③ 설정        ──← 내 여행──▶               ② 마이페이지
  어디서든 로그아웃 ──▶ ① 표지
```

라우팅 규칙:
- `onAuthStateChanged(user)` 가 단일 진입점.
  - `user == null` → `screen='landing'`
  - `user != null` → 프로필/여행목록 로드 후 `screen='mypage'`
- 앱을 새로 열거나 새로고침하면 로그인 상태여도 **항상 마이페이지**로 간다(편집기로 복귀하지 않는다). 미저장분은 로컬 캐시에 남아 해당 여행을 다시 열 때 복구된다(§6.5).

## 3. 데이터 모델

### 3.1 Firestore

| 경로 | 내용 |
|---|---|
| `users/{uid}` (문서) | `{ avatarId: string, tripOrder: string[] }` — 프로필/설정. 언어·테마는 이후 여기 필드 추가. |
| `users/{uid}/trips/{tripId}` (문서) | 여행계획 1개. 아래 필드. |

`users/{uid}/trips/{tripId}` 문서 필드:

```
{
  data:       string,   // JSON.stringify(tripState) — 편집기가 쓰는 전체 상태
  title:      string,   // 목록 표시용 (비정규화)
  startDate:  string,   // days 중 가장 이른 date, 없으면 ""
  endDate:    string,   // days 중 가장 늦은 date, 없으면 ""
  dayCount:   number,    // tripState.days.length
  updatedAt:  Timestamp  // serverTimestamp()
}
```

`tripState` 는 현재 v1 `state` 구조와 동일:
`{ title, travelers[], days[{ id, date, label, items[{ id, time, place, memo, expenses[] }] }], notes[], links[] }`

**저장 포맷은 JSON.** CSV 등은 쓰지 않는다(중첩 구조라 부적합, 왕복 안전성·내장 파서 이점 상실).
`title`/`startDate`/`endDate`/`dayCount` 를 밖으로 복제하는 이유: 마이페이지가 여행 5개의 `data` JSON을 모두 파싱하지 않고 목록을 그리기 위함. 편집기에서 저장할 때마다 이 필드들도 함께 갱신한다.

### 3.2 순서 관리

`users/{uid}.tripOrder` 는 tripId 배열. 마이페이지 목록은 이 배열 순서대로 렌더한다.
- 새 여행 생성 → 배열 끝에 append
- 삭제 → 배열에서 제거
- 순서 편집(§6.3) → 배열 재배치 후 문서 저장
- 로드 시 `tripOrder` 에 없는 trip 이 있으면 끝에 덧붙이고, `tripOrder` 에만 있고 실제 없는 id 는 제거하여 자가 치유.

### 3.3 localStorage (편집 중 여행 저장 = 로컬 캐시)

| 키 | 값 |
|---|---|
| `ttv2-current-trip` | `{ tripId, data, dirty: boolean, localUpdatedAt: number }` — 지금 편집기에서 열어둔 여행 1개 |
| `travel-template-mode` | `'edit' | 'view'` — 기존 유지(전역, 여행 무관) |

- 로컬 캐시는 **여행 1개**만 담는다(현재 열려 있는 것).
- 비로그인 상태에서는 편집기 자체가 없으므로 로컬 캐시도 생성되지 않는다.
- 기존 v1 키(`travel-template-data-v1`)는 더 이상 쓰지 않는다.

### 3.4 보안 규칙

기존 규칙이 하위 컬렉션까지 재귀 커버하므로 **변경 불필요**:
```
match /users/{userId}/{document=**} {
  allow read, write: if request.auth != null && request.auth.uid == userId;
}
```

### 3.5 v1 데이터 정리 (1회, 수동)

사용자가 Firebase 콘솔에서 `users` 컬렉션을 직접 삭제한다(데이터 삭제는 코드로 하지 않는다). v2는 옛 `data` 필드를 읽지 않으므로 지우지 않아도 동작에는 지장이 없다.

## 4. 표지 화면 (landing) — 신규

비로그인 시 유일하게 보이는 화면. 로그인이 앱 사용의 전제.

구성:
- 앱 아이콘(`icon.png`) + 이름 "Travel Template"
- 한 줄 소개 (예: "여행 일정·지출·메모를 한 곳에서")
- 기능 미리보기: 스크린샷 1~2장 또는 핵심 기능 3줄 요약 (일정표 / 지출 기록 / PDF·공유)
- **구글 로그인 버튼** (유일한 CTA) — 기존 `loginWithGoogle()` 재사용
- 데모/둘러보기는 넣지 않는다.

문구·이미지 세부는 구현 시 확정.

## 5. 마이페이지 (mypage) — 신규

로그인 후 항상 여기로 진입. 레이아웃은 확정된 "A안(목록 중심)".

구성(위→아래):
1. **상단 바**: 선택한 아바타 + 사용자 이름만. 탭하면 → 설정 화면(③). 이메일·로그아웃은 여기 없음.
2. **"내 여행"** 제목 + **`N / 5`** 카운트.
3. **여행 카드 목록** (`tripOrder` 순서):
   - 카드 내용: 제목 / 날짜 범위 / 일수
     - 제목 없음 → "제목 없는 여행"
     - 날짜 없음 → "날짜 미정"
     - 일수 → `dayCount` + "일" (예: "4일")
     - 날짜 범위 표기 예: `2026-03-14 → 03-17 · 4일`
   - 카드 왼쪽: **위/아래 화살표**(항상 표시) — 인접 슬롯과 한 칸 교체
   - 카드 탭 → 편집기(④)로, 해당 trip 로드
   - 카드 우상단 **✕** → 삭제(§6.4)
   - 카드 **롱프레스(~0.5초)** → 이동 모드(§6.3)
4. **`＋ 새 여행 만들기`** 버튼 (점선). 항상 활성 상태로 보인다.
   - 여행 < 5 → 즉시 생성(§6.1)
   - 여행 == 5 → 5개 제한 팝업(§6.2), 생성 안 함
5. 맨 아래 **`⚙ 내 정보 및 옵션`** 행 → 설정 화면(③)

## 6. 마이페이지 동작

### 6.1 새 여행 생성

"＋ 새 여행 만들기" 탭 (여행 < 5):
1. `defaultState()` 로 새 `tripState` 생성
2. `users/{uid}/trips/{autoId}` 문서 즉시 생성 (`data` = 빈 상태 JSON, `title=""`, 날짜 `""`, `dayCount=1`, `updatedAt`)
3. `tripOrder` 끝에 `autoId` append, `users/{uid}` 저장
4. `ttv2-current-trip` 로컬 캐시 셋 (`tripId=autoId`, `dirty=false`)
5. `screen='editor'` 로 전환, 편집기 렌더

빈 여행도 슬롯 1칸을 차지한다. 실수로 만든 빈 여행은 삭제로 정리.

### 6.2 5개 제한

여행이 5개인 상태에서 "＋ 새 여행 만들기" 탭 → **팝업 모달**:

> 여행계획은 최대 5개까지 저장할 수 있어요.
> 멤버십을 변경하여 여행계획을 더 늘려보세요.

닫기 버튼만. 생성은 일어나지 않는다. (멤버십 기능은 아직 없음 — 문구만.)

### 6.3 순서 편집

**위/아래 화살표**: 각 카드 왼쪽에 상시 표시. 누르면 `tripOrder` 에서 해당 항목을 인접 항목과 swap → 목록 재렌더 → `users/{uid}` 저장. 맨 위 항목의 ▲, 맨 아래 항목의 ▼ 는 비활성.

**롱프레스 드래그**:
- 카드를 ~0.5초 누르면 **이동 모드** 진입
- 시각 표시: 드는 카드가 살짝 커지고 그림자, 나머지 카드는 자리를 벌린다
- 드래그하여 위치 이동, **드롭하면 이동 모드 자동 해제**
- 드롭 시 `tripOrder` 재배치 → `users/{uid}` 저장
- 터치(모바일) + 마우스(데스크톱) 모두 지원. 최대 5개라 구현 범위는 좁다.
- 롱프레스로 진입하지 않은 일반 탭은 기존대로 "여행 열기"로 동작해야 한다(임계시간으로 구분).

정렬 기준은 이 수동 슬롯 순서뿐이다. "최근 수정 순" 자동 정렬은 채택하지 않는다.

### 6.4 삭제

카드 ✕ → **확인 팝업**:

> 이 여행을 삭제할까요?
> 되돌릴 수 없습니다.

[삭제] / [취소]. 삭제 시:
1. `users/{uid}/trips/{tripId}` 문서 삭제
2. `tripOrder` 에서 제거 → `users/{uid}` 저장
3. 그 tripId 가 `ttv2-current-trip` 로컬 캐시와 같으면 캐시 제거
4. 목록 재렌더

### 6.5 동기화 / 오프라인 (편집기와 공유되는 규칙)

옵션 B: Firestore 가 주 저장소, localStorage 는 현재 여행 캐시.

- **클라우드 → 로컬**: 여행을 여는 순간 1번만. 이후 세션 중 클라우드가 로컬을 덮어쓰지 않는다.
- **로컬 저장**: 입력 시마다 즉시(`ttv2-current-trip` 갱신, `dirty=true`).
- **클라우드 저장**: 입력이 멈추고 약 1초 뒤(디바운스). 성공하면 `dirty=false`.
- **강제 저장**: "← 마이페이지"로 나갈 때 밀린 변경분을 1회 강제 flush. 실패(오프라인)하면 `dirty` 유지.
- **다시 열 때**: `ttv2-current-trip.tripId` 가 열려는 여행과 같고 `dirty=true` 면 → 로컬 캐시 버전을 채택하고 즉시 클라우드로 올림. 아니면 클라우드 버전 로드.
- **오프라인 편집**: 로컬에는 계속 저장됨. 클라우드만 실패. 같은 기기에서 계속 쓰는 한 손실 없음. (다른 기기로 열면 그 기기는 클라우드의 옛 버전을 받는다 — 알려진 한계, 수용.)

**미동기화 표시**: 편집기 상단 한 자리(기존 `syncStatus` 요소 재사용).
- 동기화 정상: **숨김**
- `dirty` + 클라우드 저장 실패 상태: 같은 자리에서 두 문구를 ~2초 간격으로 번갈아 표시
  - `클라우드 저장 안됨`
  - `인터넷 연결 확인`
- 다시 동기화되면 숨김.

## 7. 설정 화면 "내 정보 및 옵션" (settings) — 신규

구성:
- 상단 **`← 내 여행`** (마이페이지로)
- **계정 블록**: 아바타(크게) + 이름 + 이메일. (여기서만 이메일 노출.)
- **아바타 변경** 행 → 탭 시 **팝업 모달**:
  - 동물 이모지 8종, 한 줄 4개 × 2줄: 🐶 강아지 / 🐱 고양이 / 🐰 토끼 / 🐯 호랑이 / 🦊 여우 / 🐻 곰 / 🐼 판다 / 🦁 사자
  - `기본(✈)으로` 되돌리기 + `저장` 버튼
  - 저장 시 `users/{uid}.avatarId` 갱신. 값: `'default' | 'dog' | 'cat' | 'rabbit' | 'tiger' | 'fox' | 'bear' | 'panda' | 'lion'`
  - `default` 렌더 = ✈ 이모지(네이비 배경). 그 외 = 해당 동물 이모지.
  - 아바타는 마이페이지 상단 바와 이 화면 계정 블록에 반영.
- **언어** 행 — "준비 중" 배지, 비활성
- **컬러 테마** 행 — "준비 중" 배지, 비활성
- **로그아웃** 버튼 (기존 `logoutUser()` 재사용) → 표지 화면으로

## 8. 편집기 (editor) — 변경점만

편집기 내부(일정 카드, 메모/링크/지출 탭, 날짜/시간 입력, PDF 저장, 공유, 수정/보기 모드 등)는 **그대로 둔다.**

바뀌는 것:
1. 상단 네비 영역에서 로그인/유저 정보 블록 제거. 핸드오프에서 nav 로 옮겼던 로그인 UI(`loginBtn`/`userInfo`)는 v2 편집기에 표시하지 않는다(계정은 설정 화면에서만).
2. 기존 배지 + 모드 버튼(수정/완료) 줄에 **`← 마이페이지`** 버튼 추가. 브랜딩/아바타/이름 없음. 편집 영역은 넓게 유지.
3. 저장 대상 변경: `users/{uid}` 단일 문서 → `users/{uid}/trips/{currentTripId}`.
   - `save()` = 로컬 캐시 갱신(+`dirty`)
   - `saveToCloudDebounced()` = `trips/{currentTripId}` 에 `{ data, title, startDate, endDate, dayCount, updatedAt }` 병합 저장
4. `syncStatus` 요소를 §6.5 의 미동기화 표시로 재사용.
5. `currentTripId` 는 편집기 진입 시 세팅(마이페이지에서 카드 탭 또는 새 여행 생성). 편집기에 직접 진입하는 경로는 없다.

`startDate`/`endDate` 계산: `tripState.days` 의 `date` 중 non-empty 최소/최대. `dayCount = tripState.days.length`.

## 9. 범위 밖 (이번에 하지 않음)

- v1 → v2 데이터 마이그레이션 / 가져오기 버튼
- 언어(다국어), 컬러 테마 실제 동작 (자리만 만든다)
- 멤버십/결제, 5개 초과 잠금 해제
- 실시간 공동 편집(협업 모드)
- URL 라우팅 / 브라우저 뒤로가기 대응
- 비로그인 편집 / 로컬 전용 사용
- 엑셀·CSV·JSON 내보내기/불러오기 (제거된 상태 유지)

## 10. 구현 메모

- 단일 `index.html` 유지. 4개 화면을 컨테이너 `<section>` 으로 두고 `screen` 상태에 따라 하나만 보이게.
- Firebase compat SDK 10.14.1 그대로. `firebaseConfig` 그대로.
- `onAuthStateChanged` 하나로 표지↔마이페이지 라우팅.
- 마이페이지 로드 순서: `users/{uid}` 문서(→ `avatarId`, `tripOrder`) + `users/{uid}/trips` 컬렉션 → `tripOrder` 순으로 카드 렌더.
- 롱프레스/드래그: 포인터 이벤트로 터치·마우스 공통 처리. 임계시간(~500ms)으로 탭과 구분.
- 기존 함수 재사용: `loginWithGoogle`, `logoutUser`, `defaultState`, `rebuildAll`, `setMode`, 편집기 렌더 로직 전부.

## 11. 테스트 관점

- 비로그인 → 표지만 보임, 로그인 버튼 외 진입로 없음
- 로그인 → 마이페이지 진입, 여행 0개일 때 빈 목록 + "새 여행 만들기"만
- 새 여행 생성 → 즉시 목록에 나타남, 편집기 진입, `tripOrder` 반영
- 여행 5개에서 새로 만들기 → 팝업, 생성 안 됨
- 위/아래 화살표, 롱프레스 드래그로 순서 변경 → 새로고침 후에도 유지
- 삭제 → 확인 팝업 → 목록·`tripOrder`·(해당 시)로컬 캐시에서 제거
- 편집 → 1초 뒤 클라우드 저장, 오프라인 시 로컬만 저장 + 미동기화 문구 번갈아 표시, 복구 시 자동 flush
- 편집 중 새로고침 → 마이페이지로, 해당 여행 재오픈 시 미저장분 복구
- 아바타 변경 → 마이페이지 상단·설정 계정 블록에 반영, 새로고침 후 유지
- 로그아웃 → 표지로
